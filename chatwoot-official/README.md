# Волшебно тут CRM для Android

Клиент 0.8.0 основан на исходном коде [Chatwoot Mobile v4.11.5](https://github.com/chatwoot/chatwoot-mobile-app/releases/tag/v4.11.5), коммит `394ed529387526321a85eb95a4cc2fa89a21cea6`. Исходники входят в репозиторий как Git-подмодуль `upstream`. Лицензия MIT и уведомление Chatwoot Inc. сохранены в исходниках и внутри APK в `assets/Chatwoot-LICENSE.txt`.

## Установка на Honor

1. Откройте [GitHub Releases](https://github.com/myximka-netizen/amazy-apart/releases) и скачайте APK версии 0.8.0. Если браузер попросит, разрешите ему установить этот APK.
2. При установленной подписанной версии 0.7.0 Android предложит «Обновить». Оставьте её на телефоне. Пакет обеих версий — `ru.amazy.crm.nativeclient`, коды версий — 6 и 7.
3. Подключите Tailscale. Войдите с почтой и паролем оператора Chatwoot. Старый клиент сохраняет в Android Keystore персональный API-токен. Официальный клиент получает заголовки сессии `access-token`, `client`, `uid` при входе, поддерживает MFA и сохраняет сессию между запусками. Повторный вход нужен при переходе на эту версию. История диалогов и контакты хранятся на сервере.
4. Приложение открывает аккаунт 2, если оператор состоит в нём. Русский выбран при первом запуске. Светлая и тёмная темы по умолчанию следуют настройке телефона. Разрешите уведомления. Разрешение на микрофон понадобится при первой записи.
5. Проверьте сообщения в приложении, затем выполните [проверку Firebase и доставки на Honor](server/README.md).

Резервная [ветка 0.7.0](https://github.com/myximka-netizen/amazy-apart/tree/chatwoot-native-client) содержит прежний Java-клиент. Android не устанавливает APK с кодом 6 поверх кода 7 обычным обновлением. На действующем телефоне вернуться к интерфейсу 0.7 без очистки можно отдельной подписанной сборкой старого исходника с более высоким кодом версии.

## Устройство клиента

React Native 0.86.0, React 19.2.3, Expo SDK 57, Hermes, React Navigation, Redux Toolkit и Redux Persist. Версии библиотек и патчи зафиксированы оригинальным `pnpm-lock.yaml`. Интерфейс, шрифт Inter, жесты, темы, списки, просмотрщики и компоновка экранов взяты из upstream. Axios обслуживает API, Action Cable подключается к `wss://desktop-to6ives.taile101ff.ts.net/cable`. Android использует React Native Firebase Messaging. Приложение формирует Android-проект через Expo prebuild и собирается Gradle без аккаунта EAS.

В `deployment.json` заданы название, версия, пакет, проект Firebase, хост и стартовый аккаунт. `prepare.sh` применяет изменения из `mobile.patch`, подставляет готовый логотип сайта и существующий клиентский конфиг Firebase. При обновлении 0.7 сохраняется прежний идентификатор FCM-подписки устройства, при ротации FCM-токена подписка регистрируется заново. Токен доступа старой CRM не переносится в React Native.

## Сборка и выпуск

На Linux/macOS с Git, JDK 17, Node 22.22.2+, pnpm 10.11.0 и Android SDK выполните команды из корня репозитория. Нужны Android API 36, build-tools 36.0.0 и NDK 27.1.12297006.

```sh
git submodule update --init chatwoot-official/upstream
bash chatwoot-official/prepare.sh
cd chatwoot-official/app
corepack pnpm install --frozen-lockfile
corepack pnpm exec jest --maxWorkers=2
corepack pnpm exec expo prebuild --platform android --clean --no-install
python3 ../native.py
cd android
EXPO_PUBLIC_MINIMUM_CHATWOOT_VERSION=4.1.0 SENTRY_DISABLE_AUTO_UPLOAD=true ./gradlew :app:assembleRelease -PreactNativeArchitectures=arm64-v8a,x86_64
```

Локальная команда создаёт неподписанный release APK. Workflow **Official Chatwoot Android** подписывает готовый файл ключом `amazy_crm` из `AMAZY_ANDROID_KEYSTORE_B64` и `AMAZY_ANDROID_KEYSTORE_PASSWORD`. Приватные ключи не нужны в рабочей копии. До публикации CI сверяет реальный сертификат, пакет, код версии и MIT-лицензию, ставит оригинальный подписанный 0.7.0 в эмулятор, обновляет его через `adb install -r`, проверяет время первой установки и запускает русскую форму входа дважды. APK содержит ARM64 и x86_64. SHA-256 сертификата старой версии — `7ed3eeb141300d194d37b95e614cacb749f4fb47d879e14e6a329ca452ecd739`.

Для следующего выпуска увеличьте `versionCode` и `version` в `deployment.json`, обновите заметки и отправьте изменения в `chatwoot-official-android`. До проверки на рабочем устройстве GitHub помечает такую сборку как предварительную. Выпуски имеют отдельные теги `crm-android-v…`, опубликованные APK не перезаписываются. К каждому новому APK прилагается контрольная сумма. Старый APK в отдельном релизе служит постоянным образцом для проверки обновления.

## Что проверять на рабочем аккаунте

| Сценарий | Проверка в установленной сборке |
| --- | --- |
| Диалоги, входящие, история и непрочитанные | Отправьте из тестового Telegram-аккаунта новое сообщение. Сверьте текст и счётчик на ПК и на Honor, откройте диалог, загрузите более раннюю историю. |
| Обычный ответ, цитата и заметка | Ответьте на конкретное сообщение в тестовом чате. Проверьте доставку в Telegram, затем добавьте внутреннюю заметку и проверьте её видимость только у операторов. Поддержка цитирования зависит от канала. |
| Медиа и документы | По очереди отправьте фото, короткое видео и PDF с телефона. Откройте полученное в Telegram и предпросмотр в CRM. |
| Голосовые | Разрешите микрофон, запишите 5 секунд, отправьте запись и воспроизведите её с обеих сторон. Затем проверьте входящее голосовое из Telegram. |
| Готовые ответы и поиск | Вставьте сохранённый ответ. Найдите тестовый диалог по контакту и тексту сообщения. Откройте карточку клиента. |
| Фильтры, сортировка и действия оператора | Выберите входящий канал, оператора, порядок сортировки. Измените метку, приоритет, команду, оператора и статус тестового диалога. Подтвердите изменения на ПК. |
| Сеть и темы | Отключите сеть телефона, создайте входящее сообщение из тестового канала, включите сеть. Проверьте загрузку пропущенного сообщения, отсутствие дубля и последующий обмен без ручного перезапуска. Переключите светлую и тёмную тему. |
| Уведомления | Проверьте отдельно свёрнутое приложение, заблокированный экран и открытие нужного диалога из системного уведомления. Порядок проверки и диагностические команды приведены в руководстве по Firebase. |

Официальный README указывает Chatwoot 3.13.0+, а шаблон окружения этого тега задаёт порог предупреждения 4.1.0. Сборка использует порог из шаблона. Версию конкретного Docker-контейнера и доступность функций его редакции показывает проверка в рабочей сети.

# Все входящие сообщения на Honor

Правило предназначено для Chatwoot 4.19.1, аккаунта 2 и оператора 2. На каждое новое публичное входящее сообщение, в том числе вложение, Sidekiq использует штатную очередь push, Firebase и ссылку на диалог. Правило действует в новых и старых доступных оператору диалогах, включая неназначенные и назначенные другим людям. Chatwoot проверяет доступ к диалогу и блокировку контакта. Исполнитель и список участников сохраняются.

## Установка в Windows

Запустите в PowerShell на компьютере, где работает Docker Desktop. Во время установки кратко перезапускается Sidekiq. Скрипт определяет текущий Compose-проект по работающему контейнеру, скачивает модуль с проверкой SHA-256, добавляет одну доступную только для чтения привязку в используемый файл Compose и проверяет итоговую конфигурацию до записи. При ошибке запуска или активации он восстанавливает прежний Compose-файл. Конфигурация сохраняется при перезапуске Windows и пересоздании контейнера из тех же файлов.

```powershell
Set-Location C:\chatwoot_amazy_start
$installer = Join-Path $env:TEMP 'amazy-incoming-push.ps1'
curl.exe --fail --show-error --silent --location 'https://raw.githubusercontent.com/myximka-netizen/amazy-apart/chatwoot-official-android/chatwoot-official/server/incoming/install.ps1' --output $installer
if ($LASTEXITCODE -eq 0) { powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File $installer }
```

Успех обозначается строкой `incoming_push_ready account=2 operator=2`. Включаются переключатели новых сообщений в назначенных диалогах и в диалогах с участием оператора. Остальные настройки сохраняются. Дополнительные уведомления используют тип «сообщение в диалоге с вашим участием». Если у оператора включена почта для этого же типа, Chatwoot также применяет его почтовые настройки. Отдельный переключатель «Новый диалог создан» может добавить уведомление о самом создании диалога.

**Чтобы также отключить штатное автоназначение** во всех существующих каналах аккаунта 2, добавьте `-DisableAutoAssignment` после `$installer` в последней строке. Уже назначенные диалоги сохраняют оператора. Правила автоматизации с явным действием «Назначить оператору» действуют отдельно. Каналы, созданные впоследствии, имеют собственную настройку автоназначения.

## Проверка

1. В мобильной вкладке «Диалоги» выберите исполнителя «Все». Возьмите свой тестовый доступный диалог без ответственного.
2. Сверните CRM и отправьте сообщение гостя из второго Telegram-аккаунта. Сверьте содержание уведомления и откройте его. Проверьте тот же диалог и пустое поле ответственного.
3. Заблокируйте Honor и отправьте в этот же чат ещё одно сообщение. Проверьте второе уведомление и переход. Если проверяете диалог коллеги, используйте тестовый диалог с назначенным оператором. Убедитесь, что назначение сохранилось.

## Привязка вручную и отключение

Если файл Compose написан в нестандартном формате, установщик остановится до изменения исходной конфигурации. Файл `amazy_incoming_push.rb` находится в каталоге проекта. Добавьте указанную ниже строку в существующий список `volumes` сервиса `sidekiq`, затем запустите установщик ещё раз. Относительный путь отсчитывается от каталога проекта.

```yaml
      - "./amazy_incoming_push.rb:/app/config/initializers/amazy_incoming_push.rb:ro"
```

Чтобы отключить правило, удалите только эту строку привязки и примените исходные файлы Compose командой `docker compose up -d --no-deps sidekiq` с теми же аргументами `-f`, которые использует ваш стек. Push для обычных назначений и участников управляется в профиле оператора. Если использовали `-DisableAutoAssignment`, автоназначение можно вернуть отдельно для нужных каналов. Перед обновлением сервера на другую версию проверьте совместимость модуля на стенде.

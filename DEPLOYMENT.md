# Публикация и маршрутизация в Timeweb Cloud App Platform

## Что находится в репозитории

Сайт собирается Vite и затем пререндерит 42 страницы (14 маршрутов на русском,
английском и китайском). Каждый маршрут имеет собственный index.html.
Основной адрес — https://amazy-apart.ru; страницы используют завершающий слеш:
например, /apartments/, /en/contacts/. Служебные файлы robots.txt,
sitemap.xml, изображения и JS/CSS остаются файлами без добавления слеша.

Ошибки рендерятся в dist/404.html с noindex, без canonical и hreflang.
Файл ошибки не входит в sitemap. Наличие 404.html само по себе не меняет
HTTP-статусы хостинга.

## Настройки сборки

- Репозиторий: myximka-netizen/amazy-apart.
- Ветка: main.
- Node.js: 22 (как в GitHub Actions).
- Команда: npm ci && npm run build && npm run verify:build.
- Директория результата: dist.

Используйте npm run build целиком: отдельный vite build пропускает пререндеринг.
GitHub Actions выполняет проверки, но не управляет настройками Timeweb.

## Настройка реальных HTTP 404

Перед изменением проверьте, что на привязанном домене уже опубликована сборка
с отдельными HTML-страницами. Например, /contacts/ должна отдавать собственный
текст и canonical https://amazy-apart.ru/contacts/ в исходном HTML.

1. Timeweb → App Platform → нужное приложение → Настройки.
2. В строке «Настройки веб-сервера» нажмите «Настроить».
3. Выключите SPA Fallback.
4. Сохраните и дождитесь завершения деплоя.

При включённом SPA Fallback отсутствующий путь получает index.html главной.
При выключенном платформа может использовать подготовленный 404.html.
Обязательно проверьте именно HTTP 404, а не только надпись «404» в браузере.
Не включайте SPA Fallback обратно для исправления отдельного маршрута:
проверьте, что его HTML действительно создан и попал в dist.

Официальная инструкция:
https://timeweb.cloud/docs/apps/reverse-proxy

## Домены и постоянные перенаправления

Сначала убедитесь, что основной домен обслуживается актуальным приложением.
В проверке от 12 октября основной и технический домены отдавали разные сборки.
Перенаправление технического домена до исправления этой привязки отправит
посетителей на прежнюю версию.

После выравнивания сборок в тех же настройках веб-сервера добавьте host-правила:

| Source | Destination | Code |
| --- | --- | --- |
| www.amazy-apart.ru | amazy-apart.ru | 301 |
| myximka-netizen-amazy-apart-4060.twc1.net | amazy-apart.ru | 301 |

Timeweb позволяет выбирать только домены, привязанные к этому приложению.
Сначала проверьте их привязку и SSL. Перенаправления должны сохранять путь
и параметры запроса, например /contacts/?utm_source=test.
Перенаправление HTTP → HTTPS также должно оставаться постоянным.

Канонические страницы публикуются как директории с index.html. Проверьте,
что /apartments перенаправляется на /apartments/ с кодом 301 или 308,
включая английские и китайские маршруты. Если платформа вместо редиректа
возвращает 200, настройте path-правила в панели; не используйте перенаправление
всех неизвестных адресов на главную. У Timeweb есть ограничение на 10 правил
редиректа; для массовых правил потребуется согласовать конфигурацию с хостингом.

## О файле _redirects

public/_redirects копируется в dist и предназначен только для хостингов,
которые поддерживают этот формат. Последнее правило возвращает 404.html со
статусом 404 вместо прежней подстановки главной страницы с кодом 200.
Правила добавления слеша не являются переносимыми между хостингами: например,
Netlify нормализует слеши до обработки правил и может создать цикл.
Поэтому единый формат задаётся в ссылках и canonical, а HTTP-перенаправления
проверяются и настраиваются на используемом веб-сервере.

Timeweb не документирует поддержку _redirects. Не рассчитывайте, что коммит
этого файла автоматически изменит серверные настройки Timeweb.
Перенаправление технического домена намеренно включается в панели только
после проверки актуальности основного домена.

## Проверки

Локальная проверка кода и всех HTML-страниц:

```bash
npm run check
npm run build
npm run verify:build
```

После деплоя (проверка делает только GET-запросы):

```bash
npm run verify:deployment -- https://amazy-apart.ru
```

После настройки доменных перенаправлений:

```bash
npm run verify:deployment -- https://amazy-apart.ru --check-hosts
```

Проверка контролирует ответы 200 и собственные canonical в исходном HTML,
постоянные перенаправления с сохранением параметров, HTTP 404 для неизвестных
маршрутов и отсутствующих ресурсов. Она завершится ошибкой, если сервер
по-прежнему подставляет главную страницу.

Проверить техническую площадку до включения перенаправления можно той же
командой с её адресом. Ожидаемые canonical всегда относятся к amazy-apart.ru.

npm run preview предназначен для просмотра сборки; его ответы не доказывают,
что Timeweb настроен правильно. Успешная сборка и успешная проверка HTTP
опубликованного сайта — разные этапы.
